# Provider and reasoning routing audit: 2026-10-05

Baseline: `a485c895f9bab1d41acfd051c99ad607c6c4387f`.
Scope: user-configurable installation, model destinations, reasoning contracts
and provider fallback persistence. The embedded router source is unchanged.

## Changes and regressions

| Surface | Result and evidence |
| --- | --- |
| Installation | `onboard` can create a private version 2 provider configuration: arbitrary provider/account order, fixed models or complete Jev-model mappings, and declared reasoning support. Wizard tests and the real installer state-machine test prove the configuration is copied without rewriting the sequence. Platform service commands in that test are mocked. |
| Existing profiles | Removed the wizard's silent substitution of an occupied intended profile with another default. A regression proves the intended path is retained and blocked before requesting a key. |
| Model identity | Legacy Astra no longer silently becomes a GPT-5.6 Sol alias or the fixed native fallback. Version 2 replacements are explicit. Attempts distinguish Jev's `selected_model` from the actual destination `model`. |
| Fallback | The attempt budget counts configured providers/accounts, including native routes in any position. Tests cover nine routes, sticky account order, recovery after exhaustion and preserving canonical input/cache identity across retries. |
| Recovery | Generation and configuration checks reject stale failure/success receipts. Configuration changes invalidate old selections and circuits. Corrupt indices, retry times and recovery state fail closed. Slow fallbacks cannot re-probe the primary within the same request. |
| Tool history | A request containing `tool_search_output` uses an explicitly configured native route without advancing the sticky provider; no native route produces a clear error. A failed forced-native request is attempted only once. |
| Reasoning | Every fallback resolves the original depth against the exact destination profile; unsupported effort is removed without losing other metadata. Model IDs with surrounding whitespace are rejected instead of silently missing their profile. Unknown support stays unknown. |
| Validation and cleanup | Invalid legacy account values now produce validation errors rather than unhashable-value exceptions. Invalid ordered configurations are rejected before collecting a key. Newly created keys/configurations are removed on failure before the install journal exists; caller-owned configurations are not modified. |

## Compatibility and acceptance boundaries

Legacy Luna/Sol routing still uses historical GPT-5.6 gateway aliases. A read-only
query of the operator's existing local OmniRoute catalog found those aliases,
but no `codex/gpt-6-*` routes. This is gateway configuration evidence only, not
proof of the upstream model identity. No such aliases or account IDs are
automatically required in a version 2 installation.

No generation request, service restart, credential change or live-profile
installation was performed. Actual provider identity, enforcement of reasoning
effort, model quality and fresh-client hook/loading acceptance remain unverified.
Linux/Windows changes have source/mock coverage here, not fresh-host execution.
The real installation smoke is restricted to disposable GitHub-hosted runners;
it was not bypassed on this host. Release packaging requires a clean committed
tree and remains a post-commit check. See [provider configuration](PROVIDERS.md)
and [reasoning acceptance](REASONING.md) for the supported contracts and live probes.
